# AI Scanner: design

A tool where you drop in any content (text, image, audio, video, document) and get back an assessment of whether it was AI-generated, using evidence that goes well beyond metadata.

Written 2026-10-19. The detector landscape moves fast; names and accuracy figures below reflect what was known as of mid-2026 and should be re-checked before relying on any one of them.

---

## 1. The honest constraint first

No detector can *prove* content is human-made, and every content-based classifier can be fooled.

- **Text** detection is the weakest. Light paraphrasing, a "humanizer" pass, or a human editing an AI draft drops most detectors to near chance. False positives land disproportionately on non-native English writers and very formulaic writing (legal, technical, short answers).
- **Images, audio and video** are more detectable today, because generators leave statistical fingerprints. But detectors trained on one generator often miss the next one, and re-encoding, resizing, cropping or screenshotting erases many of the signals.
- **Positive provenance** (a valid C2PA signature, a detected SynthID watermark) is strong evidence. Its *absence* means almost nothing, since most tools don't add it and it is easy to strip.

So the tool should never output "AI: yes/no". It should output a **likelihood with the evidence behind it**, separating *strong* signals (cryptographic provenance, watermark hits) from *probabilistic* ones (classifier scores, statistical tells), and say clearly when the evidence is inconclusive.

## 2. Architecture

```
          upload / paste / URL
                  │
          ┌───────▼────────┐
          │  Ingest & type  │  sniff MIME, unpack containers
          │   detection     │  (PDF/DOCX → text + images; video → frames + audio)
          └───────┬────────┘
                  │  one job, many "items"
   ┌──────────┬───┴──────┬───────────┬──────────┐
   ▼          ▼          ▼           ▼          ▼
Provenance  Text      Image       Audio      Video
 layer     analyzers analyzers   analyzers  analyzers
(all types)
   └──────────┴────┬─────┴───────────┴──────────┘
                   ▼
           Evidence aggregator
     (calibrated per-signal scores → overall verdict)
                   ▼
           Report: verdict band + every signal,
           highlighted regions, caveats
```

Key design choices:

- **Pluggable analyzers.** Each analyzer takes an item and returns `{signal, score 0–1, confidence, strength: strong|moderate|weak, explanation, regions?}`. New detectors drop in without touching the rest.
- **Containers are decomposed.** A PDF with embedded images gets both its text and each image scanned; a video gets sampled frames, its audio track, and temporal checks.
- **Aggregation is evidence-weighted, not averaged.** A valid C2PA manifest saying "generated by DALL·E" overrides any classifier. Classifier scores are combined only after calibration on a held-out set.
- **Verdict bands**, not percentages shown as truth: *Verified AI* (provenance/watermark), *Likely AI*, *Inconclusive*, *Likely human*, *Verified capture* (valid camera/C2PA capture signature). "Likely human" should be used sparingly.

## 3. Layer 0: Provenance (all media types)

These are the "beyond metadata" signals that are actually trustworthy, because they are cryptographic or embedded in the signal itself.

| Signal | What it is | Tooling | Strength |
|---|---|---|---|
| **C2PA / Content Credentials** | Signed manifest describing how the asset was made/edited. Adobe Firefly, OpenAI image models, Microsoft, Google, Leica/Sony/Nikon cameras, LinkedIn and others emit or preserve it. | `c2pa-python` / `c2patool` (open source, Content Authenticity Initiative) | Strong when signature validates. Absent = no information. |
| **Invisible watermarks: SynthID** | Google's watermark for Gemini/Imagen images, Veo video, Lyria audio, and Gemini text. | SynthID Detector portal; SynthID Text is open-sourced (Hugging Face Transformers), image/audio detection is Google-gated | Strong on a hit. Only covers Google models. |
| **Other invisible watermarks** | Meta's Video Seal / AudioSeal, Stable Diffusion's default `invisible-watermark` (DWT-DCT), various vendor marks. | `audioseal`, `videoseal`, `invisible-watermark` (all open source) | Strong on a hit; easy to miss after heavy edits. |
| **IPTC "digital source type"** | Field `trainedAlgorithmicMedia` set by many generators. | `exiftool` | Weak (trivially edited), but cheap to read. |
| **Classic metadata** | EXIF camera data, software tags, PNG text chunks with prompts (e.g. Stable Diffusion/ComfyUI write full prompts). | `exiftool` | Weak. Included for completeness, never decisive alone. |

## 4. Text

| Approach | How it works | Notes |
|---|---|---|
| **Zero-shot statistical: perplexity & burstiness** | Score the text under an open LM. AI text tends to have uniformly low perplexity; human text is "burstier". | Cheap, explainable, weak alone. Fooled by paraphrasing. |
| **Binoculars** (open source, 2024) | Ratio of perplexity under one model to cross-perplexity between two related models. | One of the best zero-shot methods; runs locally with two small open LMs (e.g. Falcon/Qwen pairs). Good starting point. |
| **Fast-DetectGPT** (open source) | Measures whether tokens sit at the "peak" of the model's probability curve vs. sampled alternatives. | Strong zero-shot, cheap. |
| **Supervised classifiers** | Fine-tuned RoBERTa/DeBERTa-style models trained on human vs. AI corpora. | Good in-distribution, brittle on new models/domains. Open checkpoints exist on Hugging Face; quality varies widely. |
| **Watermark detection** | SynthID Text (Gemini), any open-model watermark schemes. | Strong on hit; only for watermarked models. |
| **Stylometric tells** | Overused phrasings, uniform sentence length, list/heading structure, hedging patterns. | Useful as *explanations* for the user, not as a verdict. |
| **Commercial APIs** | GPTZero, Originality.ai, Pangram Labs, Copyleaks, Winston. | Pangram has published the strongest independent results so far. All cost money and still have false positives. |

Limits: needs ~200+ words to say anything; unreliable on code, poetry, translations, short replies; very unreliable on human-edited AI drafts. Report per-paragraph scores so users see *where* the signal is.

## 5. Images

| Approach | How it works | Notes |
|---|---|---|
| **Frequency/spectral analysis** | FFT/DCT of the image. GAN and diffusion upsampling leave periodic peaks and unnatural high-frequency falloff. | Explainable (you can show the spectrum). Weakened by JPEG recompression and resizing. |
| **Noise residual / PRNU** | Real camera sensors leave a characteristic noise pattern; generated images lack it or have a synthetic one. | Good "is this a real photo" signal; needs reasonably original files. |
| **Universal/foundation-model detectors** | Linear probe or small head on CLIP/DINOv2 features (UnivFD "Towards Universal Fake Image Detectors", 2023, and successors). | Generalizes across generators much better than older CNN detectors. Open source; a strong base for the prototype. |
| **Reconstruction error (DIRE / AEROBLADE style)** | Run the image through a diffusion model's autoencoder; generated images reconstruct with suspiciously low error. | Good on latent-diffusion outputs; compute heavy. |
| **Semantic/physical checks** | Hands, text in images, reflections, shadows, perspective. A vision-language model can be asked to point these out. | Great for *explanations*; unreliable as a classifier; modern models have mostly fixed hands. |
| **Commercial APIs** | Hive Moderation, Sightengine, Reality Defender, Illuminarty, AI or Not. | Hive and Reality Defender are widely used; free tiers exist for testing. |

Limits: screenshots, heavy compression, crops and small thumbnails lose most signals. Inpainted/edited real photos (partial AI) need region-level output, not a single score.

---

## 6. Audio (voice clones, AI music)

| Approach | How it works | Notes |
|---|---|---|
| **Spectral artifacts** | Neural vocoders leave tell-tale patterns in high frequencies, phase, and breath/silence regions. Visualize as a spectrogram. | Explainable; weakened by phone-quality compression. |
| **Anti-spoofing models** | AASIST, RawNet2, and SSL-based (wav2vec2/WavLM + classifier) models from the ASVspoof challenges. | Open source, strong on benchmarks, weaker on in-the-wild clips. |
| **Watermarks** | AudioSeal (Meta), SynthID (Lyria), ElevenLabs' own classifier for its voices. | Strong on hit. |
| **AI music detection** | Classifiers for Suno/Udio-style output (published research from Deezer and others reports high accuracy on known generators). | Fast-moving area; few mature open models. |
| **Commercial APIs** | Reality Defender, Pindrop, Resemble Detect, Hive. | Mostly aimed at voice fraud. |

---

## 7. Video

Video = frames (image analyzers on sampled frames) + audio track (audio analyzers) + checks that only exist over time:

- **Temporal consistency**: objects morphing, flicker, textures "swimming", physics violations (Sora/Veo/Kling-era artifacts).
- **Face deepfake detectors**: FaceForensics++-trained models, lip-sync mismatch (audio–visual sync) detectors.
- **Watermarks/provenance**: C2PA (OpenAI Sora, Google Veo emit it), SynthID for Veo, visible watermarks that were cropped (detectable edges).
- **Commercial**: Reality Defender, Hive, Sensity, Intel FakeCatcher.

Video is the most expensive to analyze; sample ~1 frame/sec plus scene-change frames, and cap length for the prototype.

---

## 8. Documents (PDF, DOCX, slides)

- Extract text → text analyzers (per section).
- Extract embedded images → image analyzers.
- Document metadata: producer/creator app, edit history in DOCX (`docProps`, revision IDs), which can hint at paste-in-one-go authoring. Weak signals only.

## 9. Recommended first prototype

Goal: something Oliver can use end-to-end quickly, that is honest about uncertainty, and that is built so stronger detectors slot in later.

**Scope: text + images + the provenance layer, as a local web app.** Audio, video and documents come in phase 2 (documents are cheap to add once text and images exist).

**Stack**
- Python + FastAPI backend, simple single-page frontend (drag-and-drop, paste text).
- Runs locally on a laptop; a GPU helps but isn't required for the chosen models.

**Analyzers in v1**
1. Provenance: `c2pa-python` manifest check, `exiftool` metadata + IPTC source type, PNG prompt chunks, `invisible-watermark` decode.
2. Text: Binoculars (two small open LMs) + Fast-DetectGPT as a second opinion, per-paragraph scoring, and a short list of stylometric tells for explanation.
3. Image: CLIP-feature universal detector (UnivFD-style, open weights) + FFT spectrum visualization + noise-residual check.
4. Optional, behind an API key setting: one commercial API per media type (e.g. Hive for images, Pangram or GPTZero for text) as a comparison column. Off by default.

**Output**
- Verdict band (section 2) with plain-language explanation.
- Every signal listed with its score and strength, so users see *why*.
- Visuals: highlighted paragraphs for text; spectrum/heatmap for images.
- A fixed caveat line on inconclusive or text-only results.

**Evaluation from day one**
- A small labeled test set: human text (essays, emails, forum posts incl. non-native writers) vs. outputs from several current models, and real photos vs. images from several generators, each also in "re-compressed/screenshotted" form.
- Track false-positive rate on human content as the headline metric. Wrongly accusing a human is the costliest error.

**Phase 2:** audio (AASIST/WavLM model + AudioSeal), documents (text+image decomposition), video (frame sampling + audio + temporal checks), and a calibration step that learns how to weight signals from the eval set.

## 10. Open questions for Oliver

- **Who uses it?** Personal tool, teachers checking essays, journalists verifying images? This changes how cautious the verdicts must be (education use especially needs low false positives).
- **Local only, or hosted?** Local is free and private; hosted needs a GPU server and costs money.
- **Paid APIs OK?** Commercial detectors are often more accurate but cost per scan.
